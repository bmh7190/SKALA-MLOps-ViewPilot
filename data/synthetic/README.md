# ViewPilot 합성 데이터 사용 안내

이 데이터는 실제 유튜브 수집 데이터가 아닙니다. 모델 학습 및 AIOps 흐름 시연용으로 수학적 생성 규칙과 잡음을 사용한 합성 데이터입니다. 실제 서비스 예측 정확도나 유튜브의 인과관계를 입증하지 않습니다. 생성 시드: 20261001.

## 파일별 역할

| 파일 | 영상 수 | 역할 |
|---|---:|---|
| train.csv | 3,000 | 모델 가중치와 전처리 학습 |
| validation.csv | 600 | 학습 중 조기 종료, 모델 선택, 설정 비교 |
| baseline_normal.csv | 30 | 선택·고정한 모델의 초기 운영 RMSLE 기준 B 생성 |
| test_normal.csv | 120 | 정상 운영 평가, 겹치지 않는 30개 묶음 4개 |
| test_drift.csv | 120 | 후반 성장 감소 시나리오 평가, 30개 묶음 4개 |

모든 파일에 동일한 14개 컬럼이 있고, 한 행은 독립된 영상 하나입니다. 파일 간 영상 ID와 입력 중복이 없으며 게시 시각도 순서대로 분리했습니다. 각 분할 사이에는 이전 분할의 7일 정답이 확보될 수 있도록 간격을 두었습니다. 다만 실제 채널을 재현하는 channel_id나 같은 채널의 반복 관측은 없으므로 채널 단위 일반화 검증은 할 수 없습니다.

## 컬럼 정의

| 컬럼 | 타입·단위 | 용도 |
|---|---|---|
| video_id | 문자열 | 관리용, 모델 입력 제외 |
| published_at | UTC ISO 8601 문자열 | 관리·시간순 재생용, 모델 입력 제외 |
| day1_views | 정수, 회 | 게시 후 0~24시간 조회수 |
| day1_impressions | 정수, 회 | 게시 후 0~24시간 노출 수 |
| day1_avg_view_percentage | 실수, 퍼센트 | 게시 후 0~24시간 평균 시청 비율 |
| day2_views | 정수, 회 | 게시 후 24~48시간 조회수 |
| day2_impressions | 정수, 회 | 게시 후 24~48시간 노출 수 |
| day2_avg_view_percentage | 실수, 퍼센트 | 게시 후 24~48시간 평균 시청 비율 |
| day3_views | 정수, 회 | 게시 후 48~72시간 조회수 |
| day3_impressions | 정수, 회 | 게시 후 48~72시간 노출 수 |
| day3_avg_view_percentage | 실수, 퍼센트 | 게시 후 48~72시간 평균 시청 비율 |
| subscriber_count_at_publish | 정수, 명 | 게시 당시 구독자 수, 10,000~100,000 |
| category | 문자열 | gaming, education, entertainment, lifestyle |
| target_views_day7 | 정수, 회 | 게시 후 168시간까지의 누적 조회수, 정답 |

일별 값은 누적값이 아닙니다. 평균 시청 비율 45.5는 45.5%입니다. 이 합성 데이터는 시청 비율을 0~100으로 제한하는 단순화 가정을 사용합니다. 실제 데이터의 일반적인 유효성 규칙으로 그대로 단정하지 마세요. 또한 생성 과정에서 조회수의 80%가 집계된 노출에서 발생한다고 단순 가정했으며, 조회수/노출 수를 실제 CTR로 해석하면 안 됩니다.

모든 target_views_day7은 초기 3일 조회수 합 이상입니다. 예측값, 드리프트 라벨, 생성용 잠재 변수, 목표 조회수는 모델 입력 CSV에 넣지 않았습니다. 목표 달성 오판 비율은 별도 사용자 목표 정보가 있어야 계산할 수 있습니다.

## 학습 및 추론

1. train.csv만 사용하여 스케일러·인코더와 모델 가중치를 학습합니다.
2. validation.csv로 조기 종료와 모델 선택을 합니다. 이 데이터로 gradient 학습을 하지 않습니다.
3. 조회수·노출 수·구독자 수는 log1p 후 train에 맞춘 스케일러를 사용하고, 시청 비율은 100으로 나눌 수 있습니다. 정답 log1p 학습을 선택했다면 예측 후 expm1으로 복원합니다.
4. 카테고리 순서를 gaming, education, entertainment, lifestyle로 고정한 원-핫 4차원을 사용합니다.
5. 하루 입력 순서: [조회수, 노출 수, 시청 비율, 구독자 수, gaming, education, entertainment, lifestyle]. 구독자와 카테고리는 3일 모두 반복합니다. 결과 입력 shape은 (N, 3, 8)입니다.
6. 정답은 target_views_day7 하나입니다. video_id, published_at, target_views_day7을 입력 X에 포함하지 마세요. 서로 다른 영상 행을 연결하여 시계열로 만들지 마세요.
7. 추론 API에는 정답을 보내지 않습니다. 재생 시 published_at+72시간에 예측을 저장하고, +168시간에 실제 정답을 공개합니다. 같은 시각의 여러 이벤트는 시간순으로 처리합니다.
8. 원래 조회수 단위에서 RMSLE 및 MAE를 계산합니다. 이 데이터의 누적 조회수 가정에 따라 예측값을 초기 3일 조회수 합 이상으로 보정하는 정책을 쓰면 학습 평가·API·드리프트에서 일관되게 적용하세요.

## 정상 및 드리프트 생성 가정

정상 데이터의 4~7일 추가 조회수는 초기 3일 조회수 합, 3일/1일 성장 비율, 평균 시청 비율, 구독자 수, 카테고리, 노출 관련 비율에 의존하며 별도의 로그 정규 잡음을 포함합니다. 이런 관계는 실습용 가정이지 실측 근거가 아닙니다.

- 정상: 7일 누적 = 초기 3일 누적 + 정상 생성 규칙의 후반 추가 조회수
- 드리프트: 7일 누적 = 초기 3일 누적 + 정상 생성 규칙의 후반 추가 조회수 × 0.3

드리프트에서도 입력 생성 분포는 그대로 유지하고, 새로운 독립 영상들을 생성했습니다. 따라서 입력 분포 경보보다는 정답이 도착한 뒤의 성능 저하를 시연하는 시나리오입니다. 자연스러운 표본 구성 차이는 존재합니다. 정답 전체에 0.3을 곱한 것은 아닙니다.

## 드리프트 감지

선택된 모델을 고정한 후 baseline_normal의 30개 예측으로 B를 직접 계산합니다. B는 CSV에 미리 들어 있는 상수가 아닙니다.

임계값 T = max(B * 1.3, B + 0.1).

test_normal → test_drift 순서로 재생합니다. 같은 모델 버전, 영상당 72시간 예측 하나만 사용하고 실제 결과가 확보된 순서로 30개씩 겹치지 않게 평가합니다. 초기 기준 30개는 모니터링에 재사용하지 않습니다.

- 한 묶음 RMSLE > T: WARNING
- 두 묶음 연속 RMSLE > T: DRIFT_DETECTED
- RMSLE <= T: 연속 초과 횟수 초기화
- 30개 미만: 대기, 같은 데이터로 반복 카운트 금지
- MAE는 해석·기록용이며 감지 조건에는 사용하지 않음

30개, 1.3배, 0.1, 두 묶음은 실습 정책입니다. 특정 LSTM이 반드시 경보를 낸다고 보장하지 않습니다. 기준 수집은 서비스 품질 적합성 검사와 별개입니다.

## 재학습 시 주의

이번 5개 파일은 초기 학습과 정상/드리프트 감지 검증용입니다. test_drift를 학습에 사용하기 시작하면 해당 행은 더 이상 독립 테스트가 아닙니다. 재학습 성공·교체 시연을 위해서는 추가로 변화 후 학습 데이터와 별도의 변화 후 평가 데이터를 확보해야 합니다. 기존 validation은 정상 성능 유지 확인에는 유용하지만 변화 후 적응 성능을 단독으로 판단하기에는 부족합니다. 테스트 성능을 보고 반복해서 설정을 맞추지 마세요.

## 수행한 검증

파일별 행 수·스키마·고유 ID·입력 중복·수치 범위·누적 정답 조건·CSV UTC 표기를 확인했습니다. generation_report.json에 파일 통계를 기록했습니다.

별도의 NumPy 로그 선형회귀를 train에만 학습하여 데이터가 학습 가능한 관계와 감지 가능한 변화를 포함하는지 점검했습니다. LSTM은 실행하지 않았습니다. test를 사용한 하이퍼파라미터 조정은 하지 않았습니다.

정상 4개 묶음은 모두 임계값 이하였고, 드리프트 2번째 묶음에서 연속 초과 조건을 충족했습니다. 상세 값은 smoke_test_report.json에 있습니다. 이는 합성 데이터와 간단한 점검 모델의 결과이며 실제 서비스 또는 팀 LSTM의 성능 결과가 아닙니다.
