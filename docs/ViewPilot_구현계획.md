# ViewPilot 개발 구현

## API 경로

영상 예측과 실제값 등록은 `/api/v1/videos`, 데이터 업로드·조회는 `/api/v1/datasets`,
학습은 `/api/v1/models/training`, 과거 데이터 시나리오는 `/api/v1/simulations/drift`로 구분한다.
운영 로그는 `/api/v1/logs`이며 `/health`와 `/docs`는 유지한다.
요청·응답 형식은 유지하고 실행 스크립트·API 테스트를 새 경로로 변경했다.
Swagger는 영상 성과, 데이터셋, 모델 운영, 시뮬레이션, 상태 확인으로 묶는다.

## 파일별 데이터 분리

`train.csv`와 `validation.csv`를 독립적으로 입력받는다. 기존 한 파일 내부의 비율 분할은 사용하지 않는다.
전처리와 모델 가중치는 train에서만 학습하고, validation의 로그 조회수 MSE로 조기 종료와 최적 가중치를 선택한다.
두 파일의 영상 ID 중복, 최소 크기와 정답 가용 시점도 검사한다.

## 최초 모델과 수동 기준값

최초 학습은 B가 없어도 가능하다. validation에서 선택한 모델을 활성화한 뒤
`calculate_baseline.py`로 기준 영상 30개의 RMSLE를 계산한다. 결과 B와 모델 버전을 `.env`에 직접 설정한다.
기준 영상 ID는 저장해 이후 학습·모니터링에 재사용하지 않도록 한다.
기준값은 같은 모델 버전에서 고정하고, 교체된 모델에는 이전 B를 적용하지 않는다.

## 모델과 전처리

기존 LSTM 32 → 32 → 16, Dense 16 → 1 구성을 유지했다.
제공 데이터에서는 시점별 수치 4개와 원핫 4개를 사용하므로 입력은 `(N, 3, 8)`이다.
한 행 안의 첫 3일만 시퀀스로 만들고 구독자 수와 카테고리를 세 시점에 반복한다.
수량 log1p, 시청 비율 /100 이후 train 기준으로 표준화한다.
정답은 log1p로 학습하고, 예측을 복원한 뒤 첫 3일 조회수 합 이상으로 보정한다.

## 두 운영 시나리오

정상 120개와 드리프트 앞 60개를 각 30개씩 순서대로 평가한다.
드리프트 뒤 60개는 감지에 넣지 않고 재학습 검증으로 남긴다.
실제값과 최초 예측을 SQLite에 저장하고 평가 완료 영상에 block_id를 부여한다.
동일 모델 버전·모드에서 묶음이 겹치지 않으며 서버 재시작 후에도 상태가 보존된다.

`T=max(B*1.3, B+0.1)`을 초과하면 warning, 두 묶음 이상 연속 초과하면 retrain_review를 반환한다.
기준 이하이면 연속 횟수를 초기화한다. 운영과 과거 CSV 시뮬레이션 기록은 분리한다.
시뮬레이션은 정답 포함 배치 입력이며 실시간 시계 재생은 아니다.

## 재학습과 교체

드리프트 경보 이후 자동 재학습이 켜져 있으면 마지막 두 초과 묶음의 영상 60개로 재학습한다.
시나리오 요청의 retraining_validation에 전달한 뒤 60개는 가중치 학습과 드리프트 집계에서 제외한다.
기존 모델 복제본에 전처리를 고정하고 학습률 1e-4로 최대 10 epoch 추가 학습한다.
검증 손실로 최적 가중치를 선택한 후 같은 검증 세트의 RMSLE를 기존 모델과 비교한다.
후보가 엄격히 개선됐으면 교체하고, 동점이나 악화면 원래 가중치와 포인터를 유지한다.
드리프트 임계값은 배포 기준에 사용하지 않는다. 최초 선택용 DEPLOY_RMSLE_GATE도 재학습에는 적용하지 않는다.
교체 성공 후에는 새 버전의 기준값 설정이 필요하며, 시나리오는 여기서 종료한다.

관측 후 실제값이 확보된 영상은 기존 저장 값과 일치하면 재학습할 수 있다.
검증에는 이미 관측한 영상, 기존 학습·검증 영상, 기준값 계산 영상을 재사용하지 않는다.
일반 재학습 파일 경로와 업로드 API도 유지한다.

## 검증 범위

합성 데이터로 정상 감지 → 드리프트 → 실제 추가 학습 → 동일 검증에서의 비교 → 교체 판단을 실행한다.
60/60 경계의 게시 시간 간격은 3시간이므로, 정답을 모두 확보한 뒤 수행하는 과거 데이터 시나리오다.
실시간 시간 흐름 재생이나 교체 후의 독립적인 성능 평가로 해석하지 않는다.
일반 학습·재학습의 정답 가용 시점 검사는 유지한다.
단위/API 테스트와 실제 TensorFlow·MLflow 테스트에서 미개선 시 유지 및 교체·재로딩 분기도 검증한다.
실제 수치와 조건은 scenario_results.json을 참고한다. 대시보드는 수정하지 않았다.

## 재시작 가능한 두 시나리오

`DEMO_MODE=true`이면 서버 시작 시 원본 모델·기준값과 MLflow DB를 `runtime/demo`로 복사한다.
시연의 관측·재학습·교체는 이 복사본에만 반영하고, 재시작하면 시연 상태를 다시 복원한다.
원본 모델과 관측 기록은 보존한다. 일반 모드에는 초기화를 적용하지 않는다.
정상 버튼은 `POST /api/v1/simulations/normal/run`, 드리프트 버튼은 `POST /api/v1/simulations/drift/run`이다.
두 API는 본문 없이 독립 실행하며, 정상 후 드리프트도 가능하다. 중복·동시 실행은 409로 안내한다.
CLI에는 `--scenario normal|drift|both`를 추가했다. 대시보드 파일은 수정하지 않았다.
